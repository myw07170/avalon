# 进行中对局恢复

每个账号只有一个进行中存档。首页先检查存档，再允许新建；存在存档时提供继续或放弃。恢复复用原 `game_sessions` 计费会话，不重新扣除开局额度。玩家局、观战局和 mock 局均支持恢复。未启用认证的部署使用浏览器本机存档。

## 保存和恢复边界

初始发牌、并发操作结果返回、引擎提交以及观战设置变化都会更新检查点。检查点记录完整引擎状态、已提交决策、并发批次的原始视图和已收到操作、提交游标、随机数状态、座位、人设、头像和开局语言。并发回合预留独立随机流，恢复未返回的 mock 决策不会改变后续随机序列。

存档属于驱动层私有数据。组件只能读取恢复摘要和引擎批准的视图，不能直接读取快照、隐藏身份、未结算任务票或其他玩家的 AI 心证。模型配置不包含 API Key；自带模型局恢复时需要重新填写原模型的 Key。

存档保留复盘使用的 AI 推理和操作，不重复保存 provider 的完整调试 prompt 与原始响应，避免长对局耗尽浏览器存储空间。

云端写入前先保存本机备份，写入按顺序执行。失败会停止推进并保留待同步进度，首页重试恢复时可补交同一代次的本机备份。被其他页面接管后，旧代次备份不得覆盖云端。跨设备只保证恢复已经同步的进度；未收到响应的 AI 请求需要重新发起，仍按现有模型调用计数规则计数。

“保存并退出”完成同步后释放运行权；“重开”要求明确确认放弃旧局。刷新和关闭页面只尝试释放运行权，持久化不依赖关闭事件。租约每 15 秒续期、45 秒过期；用户也可以明确接管。旧页面的存档、心跳和新模型调用都会被服务端拒绝。已被上游接收的模型请求不保证能取消。

终局先保存完成检查点，再用数据库事务写入复盘、结束会话并清理进行中存档。重复完成请求幂等；保存失败可重试，不会再次运行终局引擎。

## 数据库与接口

- `active_games`：账号唯一存档槽，包含快照、revision、epoch、writer 和租约。
- `game_start_requests`：开局请求去重及完成状态，防止网络重试重复扣额或复活旧局。
- `active_game_command`：仅 `service_role` 可执行的 `SECURITY INVOKER` RPC；按账号事务锁串行处理开局、写入、接管、计数和结束。
- 两张新表启用 RLS，撤销浏览器角色直接访问权限。所有 HTTP 入口校验登录账号，用户 ID 不接受客户端输入。

现有 `POST /api/game-sessions` 接收新客户端的初始快照和 writer ID；已有历史复盘 GET 保持兼容。

| 接口 | 用途 |
| --- | --- |
| `GET /api/active-game` | 安全摘要，不返回完整状态 |
| `POST /api/active-game/resume` | 获取存档及运行权，可明确接管 |
| `PUT /api/active-game` | 按代次和递增版本保存，重复提交幂等 |
| `DELETE /api/active-game` | 放弃指定对局并关闭关联会话 |
| `PUT /api/active-game/lease` | 续租 |
| `DELETE /api/active-game/lease` | 释放运行权；POST 用于 pagehide beacon |
| `POST /api/active-game/finish` | 原子完成复盘与会话结束 |

## 发布与验证

发布应用前先执行 `supabase/migrations/20261003225020_active_game_recovery.sql`，并保留前置迁移。无需新增生产环境变量。旧会话没有中途快照，无法补建恢复记录；既有历史复盘不受影响。不兼容或损坏的存档只能明确放弃，不自动覆盖。

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm build
pnpm exec playwright install chromium
pnpm test:browser
pnpm test:browser:cloud
```

Vitest 使用隔离 PGlite 实例运行真实迁移，验证权限、单存档、扣额幂等、接管和终局事务。浏览器测试分别验证本机刷新、多标签页，以及两个独立浏览器的账号云端恢复。云端浏览器测试运行真实 Next.js 接口，连接由隔离 PostgreSQL 支撑的 Auth/PostgREST 测试服务，不访问生产账号或真实模型。
