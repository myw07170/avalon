# 阿瓦隆规则规格

本文档是游戏引擎的唯一规则依据。实现中遇到任何规则疑问，以本文档为准；本文档没写到的情况，先补充本文档，再改代码。

## 1. 阵营与胜负

- **好人（Good）**：成功完成 3 次任务，且梅林在最终刺杀中未被命中。
- **坏人（Evil）**：满足以下任一条件即获胜。
  - 破坏 3 次任务；
  - 好人完成 3 次任务后，刺客成功命中梅林；
  - 同一轮任务中，组队提议连续被否决达到上限（见 §4.2）。

胜负判定有严格顺序：先判任务比分，再判刺杀。任务比分 3:x（好人领先）时游戏**不立即结束**，必须进入刺杀阶段。

## 3. 角色与信息可见性

### 3.1 角色清单

**好人阵营**

| 角色 | 数量 | 能力 |
| --- | --- | --- |
| 梅林 Merlin | 恒为 1 | 看到所有坏人，**莫德雷德除外** |
| 派西维尔 Percival | 恒为 1 | 看到梅林和莫甘娜两人，但不知道谁是谁 |
| 忠臣 Loyal Servant | 填充 | 无信息 |

**坏人阵营**

| 角色 | 出现条件 | 能力 |
| --- | --- | --- |
| 莫甘娜 Morgana | 恒为 1 | 在派西维尔眼中与梅林混淆 |
| 刺客 Assassin | 恒为 1 | 终局指定刺杀目标 |
| 莫德雷德 Mordred | 可选，建议 9 人以上 | 梅林看不到他 |
| 奥伯伦 Oberon | 可选，建议 7 人以上 | 不认识任何坏人队友，队友也不认识他；但梅林看得到他 |
| 爪牙 Minion | 填充 | 无特殊能力 |

刺客是独立身份，不与莫德雷德或莫甘娜合并。

### 3.3 可见性规则（实现要点）

可见性必须由一个纯函数集中计算，不要散落在各处：

```
getKnownIdentities(viewer: Role, allPlayers: Player[]): Knowledge[]
```

规则矩阵：

- **梅林** → 看到 `Morgana, Assassin, Minion, Oberon` 的身份为"邪恶"，看不到 `Mordred`。
- **派西维尔** → 看到 `Merlin` 和 `Morgana` 两个座位号，标记为"这两人中有一个是梅林"，不区分。
- **莫甘娜 / 刺客 / 莫德雷德 / 爪牙** → 互相看到对方为"邪恶"，**看不到奥伯伦**。
- **奥伯伦** → 看不到任何人。
- **忠臣** → 看不到任何人。

注意奥伯伦的双向盲区：他既不在别的坏人的可见列表里，别的坏人也不在他的可见列表里。这是最容易写错的一条。

## 4. 回合流程

一局游戏最多 5 轮任务，每轮结构如下。

### 4.1 队长轮转

- 开局随机指定 1 号队长。
- 每次组队提议后（无论通过与否），队长顺位向后移动一位，循环。
- 队长本人可以把自己选进队伍，也可以不选。

### 4.2 组队与投票

1. 队长从全体玩家中选出 §2 规定人数的队员（可含自己）。
2. **全体玩家**（含队长、含未上队者）公开投票同意 / 反对。
3. 同意票 **严格大于** 半数则通过。平票视为否决。例：5 人局需要 ≥3 票同意。
4. 否决则该轮的 `rejectCount + 1`，换下一位队长重新提议。
5. `rejectCount` 达到上限（默认 5）时坏人立即获胜，游戏结束。
6. 提议一旦通过，`rejectCount` 归零。**下一轮任务开始时也归零**——计数器是每轮独立的。

可配置变体 `forcePassOnLastAttempt`：若为 true，第 5 次提议不投票直接通过，坏人不因否决获胜。默认 false。

### 4.3 任务执行

- 只有队伍成员投票，投"成功"或"失败"。
- **好人阵营在引擎层面被禁止投失败**——这不是提示，是硬约束。合法动作列表对好人只有 `SUCCESS` 一个选项。
- 坏人可自由选择成功或失败。
- 结算：失败票数 ≥ 该轮门槛（默认 1，7 人以上第 4 轮为 2）则任务失败。
- **公开信息只有失败票的数量，绝不公开投票者身份。** 引擎内部记录来源用于复盘和结算，但任何玩家视图都必须抹掉。

### 4.4 讨论

一轮中有两个讨论窗口：

- **提议讨论**：队长报出名单后、公开投票前。每人发言一次，队长先发言解释选人理由。
- **复盘讨论**：任务结果公布后。自由发言，指认、辩解、拉票。

发言顺序建议固定为座位顺序，从当前队长开始。发言是唯一的自由文本输出，其余动作全部是结构化选择。

### 4.5 刺杀

触发条件：好人任务积分达到 3。

- 刺客在**存活的所有玩家**中指定 1 人（可以指自己，虽然没意义；实现上允许，避免死循环）。
- 命中梅林 → 坏人获胜；否则好人获胜。
- 标准规则中坏人可以商议，但最终由刺客决定。AI 版建议：先让所有坏人各发表一次推测意见，再由刺客做最终选择。

## 5. 边界情况裁决

这些是实现时一定会撞上的问题，先在这里定死：

1. **队长把自己排除在队伍外** —— 合法。
2. **连续两轮同一支队伍** —— 合法，规则不禁止重复提名。
3. **第 5 轮任务前比分已是 2:2** —— 正常进行第 5 轮，胜者定局。
4. **好人误投失败** —— 不可能发生，引擎禁止。若测试中构造出该状态，视为引擎 bug 并抛错。
5. **任务票数与队伍人数不符** —— 引擎断言失败，抛错，不做容错。
6. **刺客指定了一个不存在的座位号** —— 校验层拦截，要求重新选择，重试 2 次后随机选一名好人。
7. **游戏结束后的发言** —— 允许一个终局复盘阶段，所有身份公开，纯展示用途，不影响判定。
8. **奥伯伦投票行为** —— 他是坏人，任务票可以投失败；但他不知道队友是谁，容易误伤自己人，这是设计意图，不做任何补偿。

## 6. AI 版特有约定

- **信息隔离是第一原则**：AI 玩家的 prompt 只能由 `PlayerView` 构建，绝不能接触 `GameState` 全量数据。任何一次泄漏都会让整局游戏失去意义，且这种 bug 在表面上看不出来——AI 只会"推理得特别准"。
- **梅林的行为约束**写在 prompt 里而非引擎里：引擎不阻止梅林说出坏人名单，那是策略失误不是非法操作。
- **发言长度**建议限制在 80–150 字，太长会拖慢节奏且烧 token。
- **每局调用量估算**：5 人局约 5 轮 × (提议讨论 5 次 + 复盘讨论 5 次) + 决策调用若干 ≈ 60–80 次 LLM 调用。开发期务必做 mock 模式。
